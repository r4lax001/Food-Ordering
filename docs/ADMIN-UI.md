# หน้าแอดมินรูปแบบใหม่

/admin เริ่มที่ภาพรวม ใช้พารามิเตอร์ section สำหรับเมนูนำทาง (overview, menu, categories, tables, orders, reservations) รองรับปุ่มย้อนกลับและลิงก์ตรง เช่น /admin?section=orders

- ภาพรวม: ออเดอร์ที่ยังไม่จบ การจองยืนยันของวันนี้ เมนูพร้อมขาย และโต๊ะที่เปิดใช้งาน ข้อมูลคำนวณจากรายการล่าสุดสูงสุดหมวดละ 100 รายการ มีข้อความระบุขอบเขต ไม่ใช่ยอดรวมทั้งหมดของฐานข้อมูล
- เมนูอาหาร: การ์ดภาพ ราคา สถานะ ค้นหา และกรองหมวด/การขาย พร้อมแบบฟอร์มเดิม
- หมวดหมู่: การ์ดแยกสี จำนวนเมนูจากข้อมูลที่โหลด และลิงก์เปิดเมนูเฉพาะหมวด
- โต๊ะ: การ์ดความจุ แก้ไขหรือปิดใช้งาน ไม่มีปุ่มหรือขั้นตอนเพิ่มโต๊ะ API ยังคงห้ามเพิ่มโต๊ะ
- ออเดอร์: กรองสถานะ เปิดรายละเอียดอาหาร และเปลี่ยนสถานะผ่าน API เดิม
- การจอง: เรียงเป็นกลุ่มตามวัน/เวลา กรองวันหรือสถานะ ดูหมายเหตุ การยกเลิกยังเป็นสิทธิ์เจ้าของการจอง
- จอใหญ่ใช้แถบเมนูด้านข้าง มือถือใช้เมนูไอคอน 3 คอลัมน์ มี reduced motion และ focus สำหรับแบบฟอร์ม

ตรวจ npm --prefix frontend run build ผ่าน และ node frontend/tests/admin-redesign.mjs ผ่าน:
6 หมวดที่ความกว้าง 320/390/560/768/1024/1440/1920, ค้นหา/กรอง/ล้าง, empty state, หมวดไปเมนู, โฟกัสแก้ไข, ไม่มีเพิ่มโต๊ะ, โหลดรายละเอียดออเดอร์จริง และ request เพิ่มหมวด/เปลี่ยนสถานะแบบจำลองเฉพาะใน browser โดยไม่เปลี่ยนข้อมูลร้าน

ไฟล์หลัก: frontend/src/admin.jsx, admin-panels.jsx, admin.css

## รายชื่อผู้ใช้งาน

/admin?section=users แสดงชื่อ อีเมล สิทธิ์ วันที่สมัคร และป้ายบัญชีตัวเอง ค้นหาฝั่งเซิร์ฟเวอร์ทั้งฐานข้อมูล กรอง Admin/Customer และแบ่งหน้าละ 20 บัญชี อ่านอย่างเดียว ไม่มีการแก้ไขสิทธิ์หรือลบบัญชี

ตรวจ integration ผ่าน: 401/403/200, คอลัมน์ที่อนุญาต, search/role/pagination, invalid query และ SQL injection input
ตรวจ node frontend/tests/admin-users.mjs ผ่านกับ backend แยก: ค้นหาอีเมล กรองสิทธิ์ empty state แบ่งหน้า และหน้าจอ 320/390/768/1440px
Backend ที่เปิดก่อนแก้โค้ดต้องรีสตาร์ตเพื่อโหลด endpoint ใหม่
