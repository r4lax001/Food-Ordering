# รายงานเบื้องต้น: Food Ordering & Reservation Web Service

## ที่มาและวัตถุประสงค์

ร้านอาหารต้องจัดการรายการอาหาร คำสั่งซื้อ และการจองโต๊ะให้สอดคล้องกัน โครงงานนี้พัฒนา Web Service กลางเพื่อให้โปรแกรมฝั่งลูกค้าเรียกใช้งานผ่าน HTTP/JSON โดยแยกตรรกะและการตรวจสอบข้อมูลออกจากหน้าจอ

วัตถุประสงค์: พัฒนา REST API ด้วย Node.js/Express, ออกแบบฐานข้อมูลเชิงสัมพันธ์ด้วย MySQL, จัดการสิทธิ์ผู้ใช้ และทดสอบการทำงานทั้งกรณีปกติและข้อมูลขัดแย้ง

## วิธีดำเนินงานตามขั้นตอน

1. กำหนดขอบเขต backend, SQL, Postman และเอกสาร ยังไม่มีเว็บไซต์หรือการรับชำระเงินจริง
2. ออกแบบ 7 ตารางพร้อม PK/FK โดยแยก order_items สำหรับรายละเอียดคำสั่งซื้อ และใช้ข้อจำกัดป้องกันจองซ้ำ
3. สร้าง Node.js project ติดตั้ง Express, mysql2, dotenv, bcrypt, jsonwebtoken, zod, helmet และ express-rate-limit
4. สร้าง GET /api/menu ดึงข้อมูลจาก MySQL แล้วเตรียมคำขอและ assertions ใน Postman
5. เพิ่มสมาชิก, CRUD เมนู, คำสั่งซื้อ, จองโต๊ะ, สิทธิ์ผู้ดูแล และเอกสาร API

## การทำงานของระบบ

ผู้ใช้สมัครและ login เพื่อรับ JWT จากนั้นส่ง Bearer token เมื่อเรียก API ที่ต้องการสิทธิ์ backend ตรวจบัญชีจากฐานข้อมูลทุกครั้ง ลูกค้าสั่งอาหารได้โดยเลือก menu_item_id และ quantity เท่านั้น ระบบอ่านราคาจริงและบันทึกยอดรวมพร้อมรายละเอียดใน transaction เดียว ผู้ดูแลจัดการสถานะตามลำดับที่กำหนด

ลูกค้าเลือกวันที่ รอบเวลา และจำนวนคน ระบบแสดงโต๊ะที่มีความจุพอและยังว่าง การบันทึกการจองล็อกโต๊ะและใช้ unique constraint ป้องกันคำขอพร้อมกัน การยกเลิกการจองต้องยกเลิกคำสั่งซื้อที่เกี่ยวข้องก่อน

## แผนทดสอบและผลที่ต้องตรวจ

| กรณี | ผลที่คาดหวัง |
|---|---|
| GET เมนู | 200 พร้อมเมนูจาก MySQL |
| สมัครอีเมลซ้ำ | 409 |
| ลูกค้าเรียก API ผู้ดูแล | 403 |
| ดูออเดอร์ของผู้อื่น | 404 |
| เปลี่ยนราคาเมนูภายหลัง | ราคาในประวัติเดิมไม่เปลี่ยน |
| สั่งเมนูที่ไม่มีอยู่ | 400 และไม่มีออเดอร์ค้างบางส่วน |
| สองคำขอจองโต๊ะรอบเดียวกัน | หนึ่งคำขอ 201 อีกคำขอ 409 |
| จำนวนคนมากกว่าที่นั่ง | 400 |
| ยกเลิกแล้วจองใหม่ | จองได้อีกครั้ง |
| ลบเมนูที่เคยสั่ง | เมนูหายจากรายการ แต่ประวัติยังอ่านได้ |

รัน `npm test`, `npm run test:integration` และใช้ Collection Runner ใน Postman เพื่อสร้างผลตรวจจริงในเครื่อง ไม่ใช้ผลจำลองแทน MySQL รายละเอียดผลที่ตรวจในการจัดทำอยู่ใน `docs/TEST-RESULTS.md`

## ข้อจำกัดและแนวทางพัฒนา

เป็นระบบสำหรับร้านเดียวและทดลองบน localhost เพิ่ม frontend พุงป่องสำหรับลูกค้าและผู้ดูแลแล้ว (ดู PHUNGPONG.md) ยังไม่มี payment gateway, delivery, password reset, refresh token หรือการแจ้งเตือน โต๊ะ/หมวดหมู่จัดการผ่าน API ของ admin ได้

รายงานนี้เป็นร่างอธิบาย implementation ควรเติมชื่อผู้จัดทำ รายวิชา ชื่ออาจารย์ รูปแบบอ้างอิง และภาพหน้าจอที่อาจารย์กำหนดก่อนส่ง
