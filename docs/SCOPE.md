# ขั้นที่ 1: ตรวจโจทย์และกำหนดขอบเขต

แหล่งข้อกำหนด: ขั้นตอน 1–5 ที่ผู้ใช้ระบุในแชต ยังไม่มีเอกสารโจทย์ทางการ จึงไม่อ้างว่าครอบคลุมเกณฑ์คะแนนที่ยังไม่ได้รับ

| สิ่งส่งมอบ | ขอบเขต |
|---|---|
| API | REST/JSON ด้วย Express, สมาชิก, เมนู, คำสั่งซื้อ, จองโต๊ะ |
| ฐานข้อมูล | MySQL 7 ตาราง, PK/FK, validation และข้อมูลตัวอย่าง |
| Postman | Collection, environment ตัวอย่าง, assertions และ token อัตโนมัติ |
| เอกสาร | วิธีรัน, ออกแบบฐานข้อมูล, API reference, รายงานเบื้องต้น |
| เว็บไซต์ | เพิ่ม frontend พุงป่องแล้ว ตามคำขอแบรนด์และภาพอ้างอิง; ดู PHUNGPONG.md |

สมมติฐาน: ร้านเดียว, 2 บทบาท, เงินบาท, ชำระที่ร้าน, หนึ่งโต๊ะต่อการจอง, รอบจองตายตัว 90 นาที, สั่งอาหารแบบไม่จองได้หรือผูกกับการจองของตนเองที่ยังไม่เริ่มได้

ไม่รวม: หลายสาขา, ระบบจัดส่ง, payment gateway, สต็อกวัตถุดิบ, โปรโมชัน, อีเมล/SMS, ลืมรหัสผ่าน, dashboard ยอดขาย และ deploy สู่สาธารณะ

ขอบเขตเพิ่มเติมตามขั้นที่ 6–12: CRUD โต๊ะและหมวดหมู่, GET /api/reservations/my, CORS allowlist, Postman ครบกระบวนการ, ER Diagram, Data Dictionary และการตรวจติดตั้งใหม่ ดูเอกสารฉบับเต็มใน API-COMPLETE.md

เกณฑ์ตรวจรับ: GET /api/menu คืนข้อมูลจาก MySQL จริง, ลูกค้าสมัครและเข้าสู่ระบบได้, ผู้ดูแล CRUD เมนูได้, ลูกค้าเข้าถึงออเดอร์คนอื่นไม่ได้, ราคาประวัติไม่เปลี่ยนตามราคาเมนู, จองโต๊ะพร้อมกันแล้วสำเร็จเพียงหนึ่งรายการ, เอกสารและ Postman ใช้ URL/ข้อมูลตรงกับโค้ด
