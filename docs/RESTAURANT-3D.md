# ร้าน 3D สำหรับเลือกโต๊ะ

หน้า /reservation แสดงร้าน 3D หลังค้นหาวัน เวลา และจำนวนคน ผู้ใช้สลับร้าน 3D / ผัง 2D / รายการโต๊ะได้ โดยคงโต๊ะที่เลือกไว้ ใช้ข้อมูลโต๊ะและสถานะว่างจาก API เดิม ไม่มีการเปลี่ยน schema หรือขั้นตอนยืนยันจอง

- tablePositions ใน frontend/src/components/restaurant-layout.js เป็นพิกัดกลางของผัง 2D และ 3D
- ห้องจำลองโทนไม้/ครีม มีเคาน์เตอร์ หน้าต่าง ห้องน้ำ ทางเข้า เก้าอี้ตามความจุ และพื้นที่เดินกลาง เป็นผังตัวอย่าง ไม่ใช่แบบวัดพื้นที่จริง
- ป้าย HTML ที่ติดตามกล้องมีหมายเลข ความจุ สถานะ และปุ่มที่ใช้คีย์บอร์ดได้ ปิดการเลือกโต๊ะเต็ม/ที่นั่งไม่พอ รวมถึงขณะส่งข้อมูล
- ลากหมุน ปุ่มหมุน/ซูม/คืนมุมเริ่มต้น กล้องจอเล็กมองจากด้านบนมากขึ้น ไม่มีการเคลื่อนไหวอัตโนมัติหรือการดัก scroll wheel
- โหลด Scene แบบ lazy ใช้ Three.js/React Three Fiber ที่ติดตั้งอยู่แล้ว จำกัด DPR 1.5 และ render แบบ demand
- กรณีโหลด scene ไม่สำเร็จ/WebGL ใช้ไม่ได้/context loss มีทางกลับไปผัง 2D
- โต๊ะเพิ่มเติมนอก T01–T10 แสดงรายการแยก ไม่สมมุติตำแหน่งเอง

ตรวจสอบด้วย npm --prefix frontend run build และ node frontend/tests/restaurant3d.mjs (ต้องเปิด frontend/backend และมี .local/demo-admin.json ในเครื่องพัฒนา):
ทดสอบ Canvas จริง เลือกโต๊ะ สลับสามมุมมอง มุมกล้อง/ซูม/รีเซ็ต สถานะเต็มที่จำลองผ่าน response เฉพาะ browser การกรองที่นั่ง context loss และ 12 ความกว้าง 320–2560px รวมถึงตรวจป้ายไม่ซ้อนกันในมุมเริ่มต้น ไม่สร้างรายการจองจริง

Build ผ่าน มีคำเตือนขนาด chunk Three.js ราว 923KB (gzip 248KB) เป็น dependency ที่ใช้ร่วมกับอาหาร 3D หน้าแรก ส่วนร้านเพิ่มราว 29KB (gzip 8KB)

อ้างอิงกล้อง: https://threejs.org/docs/pages/OrbitControls.html
